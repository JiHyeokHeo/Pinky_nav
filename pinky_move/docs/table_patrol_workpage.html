Pinky Pro
책상 위 왕복 주행

Pinky Pro에 원래 정의된 바닥 IR 센서 3개로 책상 끝을 확인하고, 라이다로 장애물을 감지하며, 오도메트리로 거리를 제한하는 안전 중심의 직선 왕복 주행 환경입니다.

기본 비활성 좌·중앙·우 IR 끝 감지 카메라 선택 보조 라이다 장애물 감지 0.5초 모터 Watchdog

구현 개요

Pinky Pro는 옆으로 미끄러지는 바퀴가 아니므로, 몸체 기준의 진짜 좌우 이동은 할 수 없습니다. 대신 직선으로 이동한 뒤 제자리에서 180도 회전하여 반대 방향으로 돌아오는 방식으로 왕복합니다.

⚠
실제 책상에서 바로 시험하지 마세요. 첫 시험은 바닥에서 진행하고, 책상에서는 사람이 로봇을 잡을 준비를 한 상태에서 최저 속도로 시험해야 합니다.

URDF에서 찾은 IR 센서

결론부터 말하면 Pinky Pro URDF에는 IR 센서 위치가 이미 세 군데 정의되어 있습니다. 새 위치를 임의로 만든 것이 아니라 기존 ir_l_link, ir_mid_link, ir_r_link를 그대로 사용했습니다.

가장 중요한 구분: 위치와 센서 기능은 다릅니다

URDF의 빈 link는 “센서가 어디에 붙어 있는가”만 알려주는 좌표표입니다. 기존 URDF에는 세 좌표가 있었지만 Gazebo에서 값을 만드는 센서 기능은 없었습니다. 이번 구현에서 그 좌표에 아래보기 거리 센서를 연결했습니다.

진행 방향 +X
↑
L MID R
Pinky Pro 위에서 보기 왼쪽 +Y · 오른쪽 −Y
URDF 이름base_link 기준 위치뜻
ir_l_link x=+0.0295, y=+0.020, z=−0.015m 앞쪽 왼편 책상면 확인
ir_mid_link x=+0.0295, y=0, z=−0.015m 앞쪽 중앙 책상면 확인
ir_r_link x=+0.0295, y=−0.020, z=−0.015m 앞쪽 오른편 책상면 확인

base_link는 바닥 기준 약 2.8cm 위이고 IR은 그보다 1.5cm 아래에 있으므로, 센서 프레임은 정상 책상면에서 약 1.3cm 높이입니다. x의 양수는 로봇 앞, y의 양수는 왼쪽입니다.

실물 데이터 경로

pinky_sensor_adc가 I2C 장치 /dev/i2c-1에서 세 반사 센서의 12비트 ADC 값을 읽고, /ir_sensor/range에 UInt16MultiArray로 발행합니다.

IR 반사광→ ADC 0~4095→ pinky_move

Gazebo 데이터 경로

같은 세 URDF 프레임에서 수직 아래로 한 줄의 광선을 쏩니다. 브리지가 각각을 sensor_msgs/Range로 바꾼 뒤 ir_adc_sim이 실물과 같은 /ir_sensor/range ADC 배열로 변환합니다. 따라서 pinky_move는 실물과 Gazebo를 구분하지 않습니다.

아래보기 광선→ Range(m)→ ADC 0~4095→ pinky_move

제어기가 판단하는 순서

  1. 세 입력이 모두 최신인지 확인
    0.3초 이상 새 IR 데이터가 없으면 센서 고장이나 통신 단절로 보고 주행을 막습니다.
  2. 세 곳 모두 책상 범위인지 확인
    왼쪽·중앙·오른쪽 중 하나라도 보정 범위를 벗어나면 /pinky_move/ir_safe가 false가 됩니다.
  3. 속도 명령을 0으로 변경
    활성 상태여도 STOPPED: one or more IR sensors do not see tabletop 상태를 발행하고 즉시 정지 명령을 보냅니다.
!
실물 ADC 값은 거리(m)가 아닙니다. 드라이버는 배열을 [adc[2], adc[1], adc[0]] 순서로 발행하지만 배선상의 좌·중앙·우 이름은 코드에 기록되어 있지 않습니다. 세 채널을 모두 요구하므로 안전 판단에는 순서가 영향을 주지 않지만, 채널별 보정 범위는 실제 센서를 손으로 가려가며 확인해야 합니다.

Gazebo에서 실행

네 개의 책상을 길게 연결한 월드 파일은 pinky_gz_sim/worlds/four_tables.world입니다. 월드, 로봇 스폰, 센서 브리지, 제어 노드가 한 명령으로 실행됩니다. 실행 직후에는 비활성 상태라 움직이지 않습니다.

  1. 처음 한 번 또는 코드 변경 후 빌드 
    cd ~/ws/pinky_pro
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install --packages-up-to pinky_move
source install/setup.bash
  2. 통합 시뮬레이션 실행 
    source /opt/ros/jazzy/setup.bash
source ~/ws/pinky_pro/install/setup.bash
ros2 launch pinky_move table_patrol_sim.launch.py
  3. 새 터미널에서 실물과 같은 IR ADC 배열과 결합 결과 확인 
    source /opt/ros/jazzy/setup.bash
source ~/ws/pinky_pro/install/setup.bash
ros2 topic echo /ir_sensor/range --once
ros2 topic echo /pinky_move/ir_safe --once
ros2 topic echo /pinky_move/status
    정상 책상 중앙에서는 세 ADC 값이 약 3200이고 ir_safe.data가 true여야 합니다.
  4. 세 IR이 모두 안전한 것을 확인한 뒤 이동 허용 
    ros2 service call /pinky_move/enable std_srvs/srv/SetBool "{data: true}"
  5. 정지 
    ros2 service call /pinky_move/enable std_srvs/srv/SetBool "{data: false}"

2026-09-01 실제 검증 결과

책상 중앙에서 ADC 배열 [3204, 3190, 3200]과 ir_safe=true를 확인했습니다. 진단용 0.20m/s로 75초간 180도 회전 4회를 계측한 결과 회전 명령의 부호 반전은 0회, 최대 Y 이탈은 약 1.5mm, IR false와 안전정지는 0회였습니다. 책상 끝으로 강제 이동하자 ADC가 [100, 116, 90]으로 내려가고 즉시 ir_safe=false, STOPPED: one or more IR sensors do not see tabletop으로 주행을 거부했습니다.

실제 로봇에서 실행

통합 launch는 모터·라이다·기존 pinky_sensor_adc·USB 카메라·안전 제어기를 함께 시작합니다. IR은 /dev/i2c-1, 카메라는 기본 /dev/video0을 사용합니다. 실제 IR 값은 로봇마다 달라서 최초 한 번 보정해야 합니다.

⚠
기본 설정은 IR 미보정 상태라 일부러 움직이지 않습니다. ir_adc_calibrated: false인 동안 enable 서비스를 호출해도 STOPPED: IR ADC thresholds are not calibrated가 정상입니다.

/dev/video0 사용

ros2 launch pinky_move table_patrol_robot.launch.py

/dev/video1 사용

ros2 launch pinky_move table_patrol_robot.launch.py camera_device:=/dev/video1

센서 연결 확인

ros2 topic hz /ir_sensor/range
ros2 topic echo /ir_sensor/range
ros2 topic hz /camera/image_raw
ros2 topic hz /scan
ros2 topic hz /odom

각 명령은 메시지가 계속 들어오는지 확인한 뒤 Ctrl+C로 빠져나옵니다. IR 배열에는 숫자가 정확히 세 개 있어야 하며, 필요한 토픽 중 하나라도 없으면 활성화하지 마십시오.

실물 IR ADC 보정 — 반드시 바닥에서 진행

  1. 로봇을 책상과 같은 재질의 넓은 판 중앙에 놓습니다.
    모터는 비활성 상태로 두고 ros2 topic echo /ir_sensor/range를 약 20초 관찰해 채널 0·1·2의 정상 범위를 적습니다.
  2. 사람이 로봇을 든 상태에서 센서를 한 곳씩 가립니다.
    어느 배열 번호가 반응하는지 확인하고, 책상 위 값과 책상 밖 값이 확실히 분리되는지 검사합니다. 두 범위가 겹치면 그 표면에서는 IR을 단독 안전장치로 사용하면 안 됩니다.
  3. 책상 위에서 나온 각 채널 범위를 YAML에 입력합니다.
    ir_adc_min_values와 ir_adc_max_values의 0·1·2번째 숫자는 메시지 배열의 0·1·2번째 값과 같은 순서입니다.
  4. 바닥 저속 시험을 마친 뒤 보정 완료를 켭니다.
    ir_adc_calibrated: true로 바꾸고, 센서 하나를 가리거나 판 밖으로 내밀 때 /pinky_move/ir_safe=false와 STOPPED가 되는지 먼저 확인합니다.

수정 파일: pinky_move/config/table_patrol.yaml
예를 들어 채널별 “책상 위 최소·최대 실측값”을 각각 배열에 넣습니다. 다른 로봇의 숫자를 복사하지 마세요.

카메라가 이미 실행 중이라면

USB 카메라를 중복 실행하지 말고 하드웨어와 제어기만 따로 실행합니다.

실행 중 속도 바꾸기 — Dynamic Parameters

pinky_move는 매 제어 주기마다 아래 값을 다시 읽으므로 노드를 끄지 않고도 바뀝니다. 다만 안전을 위해 먼저 /pinky_move/enable을 false로 만든 뒤 조정하세요. 

ros2 service call /pinky_move/enable std_srvs/srv/SetBool "{data: false}"
ros2 param set /pinky_move linear_speed 0.03
ros2 param set /pinky_move linear_acceleration 0.03
ros2 param set /pinky_move angular_speed 0.30
ros2 param get /pinky_move linear_speed

RQt에서는 Plugins → Configuration → Dynamic Reconfigure에서 /pinky_move를 선택합니다. 실행 중 변경은 재시작하면 YAML 값으로 돌아가므로 영구 적용은 config YAML을 수정하세요.

왜 여러 번 왕복하면 옆으로 빠졌나?

이전에는 매번 현재 yaw + 180°를 목표로 만들었습니다. 회전을 4° 일찍 끝내면 그 오차가 다음 직선에도 남고, 2m를 4° 기울어 이동할 때 약 14cm의 옆방향 오차가 생길 수 있습니다. 이것이 반복되면 폭 0.60m 상판의 옆 가장자리에 가까워집니다.

  • 최초 yaw와 최초 yaw+180° 두 절대 방향만 사용
  • 직진 중 heading과 cross-track 오차를 계속 보정
  • 옆 미끄러짐을 전진 완료 거리에서 제외
  • Gazebo 양 끝 여백을 0.40m로 확대

0.20m/s 진단에서 회전 4회 동안 각속도 부호 반전은 0회, 최대 Y 이탈은 약 1.5mm였습니다. 따라서 관찰된 주원인은 회전 지터 자체보다 기존의 방향 오차 누적 구조였습니다.

실제 왕복 거리 계산

왕복 거리 = 책상 길이 − 왼쪽 안전 여백 − 오른쪽 안전 여백
예: 책상 1.20m, 양쪽 0.25m 여백이면 1.20 − 0.25 − 0.25 = 0.70m입니다.

실물 시험 전 체크리스트

모든 항목을 직접 확인한 뒤에만 이동을 허용하세요.

문제 해결

STOPPED: configured tabletop colour is not visible
기본 HSV 범위는 갈색용입니다. 실제 책상이 흰색·검정색이면 surface_h_min/max, surface_s_min, surface_v_min/max를 실제 영상에 맞게 보정해야 합니다. 보호 기능을 끄는 대신 색 범위를 먼저 조정하세요.
STOPPED: IR ADC thresholds are not calibrated
오류가 아니라 안전 잠금입니다. 먼저 /ir_sensor/range의 세 채널을 책상 위와 밖에서 측정하고 YAML의 ir_adc_min_values, ir_adc_max_values를 입력한 뒤 ir_adc_calibrated: true로 변경합니다.
STOPPED: IR ADC data missing or stale
ros2 topic hz /ir_sensor/range를 확인합니다. 토픽이 없으면 pinky_sensor_adc가 실행 중인지, /dev/i2c-1이 존재하는지 확인하세요. 이 드라이버는 실제 Pinky Pro의 ARM64 환경에서 하드웨어 I2C를 읽습니다.
STOPPED: one or more IR sensors do not see tabletop
실제 로봇에서는 채널 하나가 보정 범위를 벗어난 상태입니다. 센서 오염·유광/검은 표면·잘못된 보정·실제 책상 끝을 확인하세요. Gazebo에서 끝 밖의 약 1.30m 값은 바닥까지의 거리이며 정상적인 위험 감지입니다.
카메라 토픽이 나오지 않음
/dev/video0 대신 /dev/video1을 지정해 보세요. MJPEG를 지원하지 않는 카메라는 launch 뒤에 pixel_format:=yuyv2rgb를 추가할 수 있습니다.
STOPPED: front path is blocked
전방 30도 범위 안에 0.20m보다 가까운 물체가 있는지 확인하세요. 라이다 렌즈와 로봇 주변 물체도 함께 확인합니다.
로봇이 예상과 다르게 움직임
ros2 topic info /cmd_vel -v로 발행자를 확인합니다. pinky_move 외에 teleop, Nav2 등이 발행 중이면 모두 종료하세요.
