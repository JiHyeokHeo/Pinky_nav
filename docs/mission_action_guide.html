Pinky 다중 로봇 Mission Action

Domain 50 관제가 하나의 Action goal로 pinky1 주차와 pinky2 순찰을 동시에 시작하는 구조다.

사용자/rqt/CLI → /execute_multi_robot_mission (Domain 50)
                         ↓
                 mission_action_server
                 ├─ /pinky1/navigate_to_pose → bridge → Domain 20
                 └─ /pinky2/navigate_to_pose → bridge → Domain 22

패키지 역할

ament_python은 Python 노드용이고, custom .msg와 .action은 rosidl CMake 생성 단계가 필요하다. 그래서 공용 인터페이스는 기존 pinky_interfaces에서, 관제 로직은 pinky_multi_robot에서 관리한다.
pinky_interfaces/                 # ament_cmake: 공용 ROS 인터페이스
  msg/RobotTask.msg
  action/ExecuteMultiRobotMission.action

pinky_multi_robot/                # ament_python: 관제 로직
  pinky_multi_robot/mission_action_server.py
  pinky_multi_robot/two_pinky_coordinator.py

인터페이스 설계

RobotTask.msg
  robot_id: pinky1 또는 pinky2
  task_type: PARK(0), PATROL(1), STOP(2)
  parking_goal: 주차 목표 PoseStamped
  patrol_waypoints: 순찰 PoseStamped 배열
  patrol_laps: 0이면 취소할 때까지 반복

ExecuteMultiRobotMission.action
  Goal: RobotTask[] tasks
  Result: success, message
  Feedback: robot_id, state, 완료 waypoint 수

처음부터 만들기

  1. 공용 interface 패키지(CMake)에 msg/action 파일을 추가한다.
  2. CMakeLists의 MSG_FILES, ACTION_FILES와 rosidl_generate_interfaces 의존성에 geometry_msgs를 등록한다.
  3. package.xml에 geometry_msgs 의존성을 추가한다.
  4. Python 관제 package.xml은 <depend>pinky_interfaces</depend>를 선언한다.
  5. Python에서 from pinky_interfaces.action import ExecuteMultiRobotMission로 import해 ActionServer를 만든다.
  6. custom action은 Domain 50에만 두고, 로봇에는 기존 Nav2 NavigateToPose만 bridge한다.

빌드·실행

cd ~/ws/pinky_pro
colcon build --packages-up-to pinky_multi_robot --symlink-install
source install/setup.bash

export ROS_DOMAIN_ID=50
ros2 run pinky_multi_robot mission_action_server
ros2 interface show pinky_interfaces/action/ExecuteMultiRobotMission

안전 원칙

두 로봇은 같은 실제 지도·같은 map 원점을 써야 pose 거리 비교가 의미 있다. PATROL의 patrol_laps=0은 계속 실행되므로 action cancel로 중단한다. 현재 서버는 Nav2 목표를 동시에 전송하며, 교차로 양보 정책은 다음 단계에서 추가한다.
