ROS 2 다중 도메인·Nav2 디버깅 노트

프로젝트: ws/pinky_pro · 중앙 관제 Domain 22 · 로봇 1 Domain 23 · 로봇 2 Domain 24

이번 증상
Domain 22에서 /clicked_point를 발행했지만 Gazebo 로봇이 움직이지 않았다. 관제 노드는 점을 수신했으나, 로봇 도메인의 Nav2 구성요소가 컨테이너에 올라오지 않아 NavigateToPose 액션 서버가 없었던 것이 원인이었다.

1. 전체 명령 흐름

Domain 22                 domain_bridge             Domain 23 / 24
/clicked_point ─▶ coordinator ─▶ /pinkyN/navigate_to_pose ─▶ /pinkyN Nav2
                                                                  │
Gazebo ◀──────────────────────── /pinkyN/cmd_vel ◀───────────────┘

도메인은 DDS 통신 범위를 나누고, 네임스페이스는 같은 도메인 안에서 로봇별 토픽·액션 이름을 나눈다. 따라서 관제에서는 /pinky1/..., /pinky2/...처럼 구분한다.

2. 가장 먼저 확인할 4단계

단계명령정상 기준
관제 수신ROS_DOMAIN_ID=22 ros2 topic info /clicked_point -vcoordinator 구독자 1개 이상
Nav2 액션ROS_DOMAIN_ID=23 ros2 action list -t/pinky1/navigate_to_pose 존재
Nav2 노드ROS_DOMAIN_ID=23 ros2 node listamcl, planner, controller, bt_navigator 등
Gazebo 입력ROS_DOMAIN_ID=23 ros2 topic info /pinky1/cmd_vel -vNav2 publisher + robot bridge subscriber

3. 이번처럼 액션 서버가 없을 때

아래가 빈 결과라면 Nav2가 실행된 것이 아니다. Domain 22에 보이는 액션은 bridge의 프록시일 수 있으므로 반드시 로봇 도메인에서 확인한다.

source /opt/ros/jazzy/setup.bash
source ~/ws/pinky_pro/install/setup.bash
ROS_DOMAIN_ID=23 ros2 component list
ROS_DOMAIN_ID=23 ros2 action list -t

비정상: component list에 컨테이너만 보이고 내부 노드가 없다. 이 경우 해당 로봇의 Nav2 터미널에서 Ctrl+C 후, 조합 노드를 끄고 다시 띄운다.

export ROS_DOMAIN_ID=23
ros2 launch pinky_navigation gz_bringup_launch.xml \
  namespace:=pinky1 use_composition:=False \
  map:=~/ws/pinky_pro/install/pinky_navigation/share/pinky_navigation/map/parking_passage_map.yaml \
  params_file:=~/ws/pinky_pro/install/pinky_navigation/share/pinky_navigation/params/pinky1_parking_passage_nav2_v2.yaml

pinky2도 ROS_DOMAIN_ID=24, namespace:=pinky2, pinky2 파라미터 파일로 바꿔 동일하게 실행한다. 이후 액션 목록에 /pinkyN/navigate_to_pose가 보여야 한다.

4. 액션은 있는데도 안 움직일 때

# 센서와 시뮬레이션 시간이 실제 흐르는지 확인
ROS_DOMAIN_ID=23 ros2 topic echo /clock --once
ROS_DOMAIN_ID=23 ros2 topic echo /pinky1/scan --once
ROS_DOMAIN_ID=23 ros2 topic echo /pinky1/odom --once

# Nav2가 내보내는 속도와 Gazebo bridge 연결을 확인
ROS_DOMAIN_ID=23 ros2 topic info /pinky1/cmd_vel -v

# 프레임 변환 점검 (map → base_footprint)
ROS_DOMAIN_ID=23 ros2 run tf2_ros tf2_echo pinky1/map pinky1/base_footprint

정상: clock, scan, odom 값이 계속 갱신되고 /pinky1/cmd_vel에 Nav2 publisher 및 bridge subscriber가 모두 보인다. TF가 없거나 맵의 벽 안에 목표점을 찍으면 Nav2는 움직이지 않을 수 있다.

5. 관제에서 목표 보내기

export ROS_DOMAIN_ID=22
ros2 run pinky_multi_robot two_pinky_coordinator

# 다른 터미널에서 (좌표는 map 좌표계)
ros2 topic pub --once /clicked_point geometry_msgs/msg/PointStamped \
  "{header: {frame_id: 'map'}, point: {x: 0.50, y: 0.60, z: 0.0}}"

중요: frame_id: 'map'을 넣는다. 현재 coordinator는 하나의 점을 두 로봇에게 전달한다. 로봇마다 다른 목표가 필요하면 coordinator에 로봇별 goal 토픽 또는 서비스 기능을 추가해야 한다.

6. 재현 가능한 점검 순서

  1. Gazebo world를 Domain 22에서 실행한다.
  2. pinky1은 Domain 23, pinky2는 Domain 24에서 spawn·robot bridge를 실행한다.
  3. 각 로봇 도메인에서 Nav2를 실행하고 ros2 action list -t로 액션을 검증한다.
  4. Domain 22에서 두 domain_bridge를 실행한다.
  5. Domain 22에서 coordinator를 실행하고 /clicked_point를 발행한다.
